# SHA-256 2048-byte SPARK benchmark

Date: 2026-08-26

The current selected schedules and four-variant benchmark are recorded in the
[`2026-08-27 schedule refresh`](2026-08-27-sha256-2048b-schedule-refresh.md).

This record contains two comparisons. The first compares clean HEAD
`18bffb60b3e10083fb77a4b7d49d1f3ce178c481` with the working tree containing
the fixed-audit embedding, grouped read commitments, and reduced peak
allocation changes. The second uses an octic SPARK control from a joint
quintic-octic invocation and subsequent full-proof quintic finalist runs to
select the schedules reported below.

The full-ZK witness relation used its 122-bit target. A native component

## Small optimization follow-up

This follow-up starts from `8000a37a3e53fe64eb25111cad888d53021805fc` and
keeps the matrix-closing protocol, proof schema, SPARK table dimensions, and
selected WHIR schedules unchanged.

#### Plain SPARK prover

The retained prover commits the padded base-field witness directly, reuses the
cached sparse-matrix multiply and bind layouts, processes base-field values
before lifting to the extension field in both sumchecks, and binds the three
matrices jointly. Tests compare the optimized sumchecks with the reference
equations and check the next transcript challenge. The 2048-byte no-ZK SPARK
Criterion mean changed from 917.614 ms to
892.712 ms, a 2.7% improvement.

Deserialized SPARK proving keys must call `prepare_for_proving` to rebuild the
derived matrix layouts. The deployment test checks that proving fails with
`MissingDerivedProverData` before this call and succeeds after it.

#### Circuit matrix entries

The retained three-input XOR constraint is

```text
(-6 + 3a + 4b + 5c)(5out + 1 - 4a - 3b) = -6.
```

For Boolean inputs, the first factor is one of `-6`, `-3`, `-2`, `-1`, `1`,
`2`, `3`, or `6`, so it is invertible in KoalaBear and uniquely determines the
parity output. The full rebuilt fixture has:

| R1CS property | Previous equation | Retained equation | Change |
| --- | ---: | ---: | ---: |
| Raw constraints | 605,424 | 605,424 | unchanged |
| Variables | 593,120 | 593,120 | unchanged |
| Total A/B/C entries | 5,285,536 | 4,850,245 | 8.24% fewer |
| SPARK union entries | 3,251,928 | 3,251,928 | unchanged |
| SPARK value domain | 4,194,304 | 4,194,304 | unchanged |

The circuit remains 1,154,776 union entries above the 2,097,152-entry domain
boundary. Crossing that boundary requires a larger circuit redesign; reducing
dense addition rows alone is insufficient because all rows wider than five
together account for fewer entries than the required reduction.

Paired proving comparisons used the same executable, fixture build
procedure, and Criterion settings for each control and candidate:

| Mode | Control mean | Retained mean | Change |
| --- | ---: | ---: | ---: |
| no-ZK DirectSparse | 46.855 ms | 45.985 ms | 1.74% faster (0.14-3.33%) |
| full-ZK DirectSparse | 69.787 ms | 66.245 ms | 5.07% faster (4.29-5.93%) |
| no-ZK SPARK | 1,979.494 ms | 1,960.000 ms | 0.98% faster, timing tie (4.24% faster to 2.68% slower) |

## Larger protocol experiments

#### Parallel fixed and read WHIR openings

The fixed-table and read-table openings depend on the same commitments and
SPARK product claims but not on each other's opening transcript. The retained
protocol derives two tagged transcript copies after those shared inputs are
fixed, runs the openings concurrently with the `parallel` feature, samples a
seal from each completed branch, and merges the seals in fixed-table,
read-table order before continuing. Proving and verification use the same
branch construction. The SPARK matrix-closing transcript version is 3; the
proof structs are unchanged.

#### Spark++ over WHIR: rejected

The experiment implemented the trusted-preprocessing one-hot and Shout core of
[Spark++](https://eprint.iacr.org/2025/105), with a weighted-value extension for
the three Spartan matrices. It did not implement Spartan++'s arithmetic-circuit
arithmetization. The experiment was sufficient to determine the commitment
cost for the target circuit.

The 2048-byte SHA-256 circuit pads the sparse support to `T = 2^22`, and a
matrix address has 40 row-and-column bits. With 20 two-bit chunks, the paper's
one-hot payload is `80T` bits, or 40 MiB. The same layout over the KoalaBear
field requires:

| One-hot payload | Size |
| --- | ---: |
| Polynomial messages | 335,544,320 field elements (1.25 GiB) |
| Initial WHIR codewords | 671,088,640 field elements (2.5 GiB) |
| Initial Merkle leaves | 2,621,440 |

Deriving one category per address chunk only lowers the logical message bound
to `40T` KoalaBear elements, or 640 MiB, before power-of-two padding, WHIR
expansion, and Merkle storage.

WHIR must Reed-Solomon encode every element and hash the resulting codeword.
Zero entries in the one-hot messages therefore do not reduce commitment work,
and the encoded codeword is dense. A mixed-base sumcheck could avoid the
prototype's 10 GiB octic copy, and a joint reduction could replace the 23
separate WHIR openings, but neither change reduces the initial codeword or
Merkle commitment work.

Changing to a commitment scheme whose prover can skip zero coefficients is not
a backend substitution. It changes the commitment and opening statements,
proof format, transcript, security composition, key lifecycle, and recursive
verifier. A hybrid construction would also need a proof connecting its sparse
commitment to the claims opened through WHIR. That is a separate proof-system
design rather than a SPARK optimization.

Decision: reject Spark++ for the WHIR-based protocol. The prototype source was
removed after recording this result. Reconsidering the construction requires a
separate commitment system and recursive verifier design.

#### Paired fixed-value/read WHIR opening (rejected experiment)

The prototype pairs the fixed-value commitment with the first read commitment.
Both initial Merkle roots and their first query
openings remain in the proof. The prover uses shared initial folding challenges,
then a transcript-derived selector combines the two residual polynomials into
one downstream WHIR chain. The selector is sampled only after both roots, OOD
answers, and opening claims are fixed. The second quintic read group remains a
separate WHIR opening.

The selector fold uses the same proximity bound as a WHIR folding round. For
the selected 120-bit quintic table target, its 17-variable residual at inverse
rate 2 needs one PoW bit. The composed SPARK budget also includes the additional
extension-field batching challenge. Setup and restored-key authentication
reject configurations that do not have identical fixed-value and first-read
PCS configurations, do not support the shared prefix fold, or exceed the
configured PoW cap.

The comparison used one benchmark executable, the selected quintic schedules,
the cached 2048-byte SHA-256 fixture, 30 Criterion samples, a 4-second warmup,
a 12-second target measurement time, and a 16-proof corpus. Times are Criterion
means; ranges are 95% confidence intervals. Proof sizes are corpus medians.

| full ZK | Witness + prove | 822.05 ms (819.84-824.29) | 847.48 ms (845.75-849.35) | 3.09% slower (2.73-3.46%) |
| no ZK | Verify | 142.79 ms (142.57-143.18) | 140.31 ms (140.11-140.64) | 1.74% faster (1.42-2.08%) |
