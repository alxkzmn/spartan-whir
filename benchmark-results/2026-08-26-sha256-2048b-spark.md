# SHA-256 2048-byte SPARK benchmark

Date: 2026-08-26

This record contains two comparisons. The first compares clean HEAD
`18bffb60b3e10083fb77a4b7d49d1f3ce178c481` with the working tree containing
the fixed-audit embedding, grouped read commitments, and reduced peak
allocation changes. The second uses an octic SPARK control from a joint
quintic-octic invocation and subsequent full-proof quintic finalist runs to
select the schedules reported below.

## Configuration

- Apple M4 Pro, 12 cores, 48 GB memory
- `rustc 1.96.0-nightly (d9563937f 2026-03-03)`
- KoalaBear octic extension for the clean-HEAD comparison; quintic and octic
  extensions for the extension comparison
- 116-bit end-to-end security target
- 2048-byte SHA-256 circuit with 605,424 raw constraints and 1,048,576 padded rows
- 3,251,928 SPARK union entries and a 4,194,304-entry value domain
- Criterion 0.8.2 with 30 samples, 4-second warmup, and 12-second target measurement time
- 16-input proof corpus
- `parallel` feature and `RUSTFLAGS='-C target-cpu=native -C debuginfo=0'`

The proving interval includes linked witness generation and proving. Setup,
proof-corpus construction, proof serialization, and output destruction are
outside the interval.

## Results

Times are Criterion means. Parenthesized ranges are 95% confidence intervals.
Proof sizes are median serialized sizes over the 16-proof corpus.

| Mode | Metric | Clean HEAD | Working tree | Change |
| --- | --- | ---: | ---: | ---: |
| no ZK | Witness + prove | 1,673.841 ms (1,634.849-1,715.112) | 1,544.994 ms (1,532.073-1,559.782) | 7.70% faster (5.33-10.07%) |
| full ZK | Witness + prove | 1,634.012 ms (1,607.694-1,667.511) | 1,477.274 ms (1,464.600-1,491.063) | 9.59% faster (7.90-11.59%) |
| no ZK | Verify | 277.913 ms (277.340-278.504) | 271.445 ms (270.845-272.162) | 2.33% faster (2.02-2.63%) |
| full ZK | Verify | 300.810 ms (300.108-301.640) | 293.513 ms (292.659-294.439) | 2.43% faster (2.04-2.83%) |
| no ZK | Proof size | 3,175,579 bytes | 2,740,145 bytes | 13.71% smaller |
| full ZK | Proof size | 4,200,384 bytes | 3,765,558 bytes | 10.35% smaller |

The proving and verification changes have `p < 0.05` in Criterion's comparison.

## Quintic SPARK selection

The candidate generator evaluated every PoW value from 0 through 22. The
previous four-bit step skipped the minimum nine-bit table budget and rounded it
up to twelve bits. Candidate validity came from the Plonky3 WHIR configuration
constructor at a 120-bit SPARK component target and a 123-bit Merkle target.
The full-ZK witness relation used its 122-bit target. A native component
calibration ranked valid candidates; the full SHA-256 Criterion run was the
final decision point because the component model had no heldout validation for
this layout.

| Component | Variables | Selected schedule |
| --- | ---: | --- |
| No-ZK witness | 20 | `quintic_constant_pow4_ff8_lir1_rsv8` |
| Full-ZK witness | 20 | `quintic_cfsr_pow6_ff8_rest6_lir1_rsv6` |
| Fixed value | 25 | `quintic_cfsr_pow9_ff8_rest4_lir1_rsv8` |
| Fixed audit configuration | 22 | `quintic_constant_pow6_ff8_lir1_rsv8` |
| Read groups | 25 and 23 | `quintic_cfsr_pow9_ff8_rest4_lir1_rsv8` |

The audit columns are embedded in the fixed-value commitment for this circuit,
so the fixed-audit schedule has no separate per-proof commitment or opening.
The shared read schedule is valid for both the eight-column and two-column
quintic groups. Its round rates are derived separately because the groups can
have different WHIR round counts.

Full-proof Criterion measurements resolved the candidates that were close in
the component model:

| Candidate change | No-ZK proving | Full-ZK proving | Decision |
| --- | ---: | ---: | --- |
| Table `rest=7` to `rest=4`, both with 9-bit PoW | 6.68% faster | 8.92% faster | Accept `rest=4` |
| Table `rest=4` to `rest=3`, both with 9-bit PoW | 6.45% slower | 9.22% slower | Reject `rest=3` |
| Table `rest=4`, 9-bit PoW to `rest=5`, 11-bit PoW | 2.58% slower | 1.13% slower | Reject `rest=5` |
| Full-ZK witness `rsv=7` to `rsv=6`, both with 6-bit PoW | n/a | 1.94% faster | Accept `rsv=6` |

All four comparisons have `p < 0.05`. The `rest=3` and `rest=5` runs stopped
after the proving groups because they were rejected on the primary metric.

## Quintic versus octic SPARK

Times are Criterion means. Parenthesized ranges are 95% confidence intervals.
Proof sizes are median serialized sizes over the 16-proof corpus. The percentage
intervals conservatively combine the independent mean confidence intervals.

| Mode | Metric | Quintic | Octic | Quintic change |
| --- | --- | ---: | ---: | ---: |
| no ZK | Witness + prove | 917.614 ms (916.056-919.297) | 1,526.037 ms (1,508.688-1,547.878) | 39.87% faster (39.07-40.82%) |
| full ZK | Witness + prove | 879.275 ms (875.906-883.212) | 1,473.336 ms (1,468.152-1,479.365) | 40.32% faster (39.84-40.79%) |
| no ZK | Verify | 152.782 ms (152.435-153.213) | 272.320 ms (271.604-273.264) | 43.90% faster (43.59-44.22%) |
| full ZK | Verify | 168.935 ms (168.561-169.373) | 293.360 ms (292.935-293.882) | 42.41% faster (42.18-42.64%) |
| no ZK | Proof size | 2,043,072 bytes | 2,740,193 bytes | 25.44% smaller |
| full ZK | Proof size | 2,729,013 bytes | 3,765,766 bytes | 27.53% smaller |

The prover-time priority selects quintic. Proof size does not act as a
tie-breaker because the proving difference is much larger than the 1% timing
tie threshold.

### Command

Set `BENCH_TARGET_DIR` to a writable temporary target directory.

```sh
RUSTFLAGS='-C target-cpu=native -C debuginfo=0' \
CARGO_NET_OFFLINE=true \
CARGO_TARGET_DIR="$BENCH_TARGET_DIR" \
SHA256_BENCH_WORKDIR=target/sha256-optimized-cache \
SHA256_ZK_BENCH_EXTENSION=spark \
cargo +nightly-2026-03-04 bench --locked --features parallel \
  --bench sha256_full_zk -- \
  --save-baseline quintic_spark_2026_08_26
```

The accepted no-ZK row and the `rsv=7` full-ZK witness baseline used:

```sh
RUSTFLAGS='-C target-cpu=native -C debuginfo=0' \
CARGO_NET_OFFLINE=true \
CARGO_TARGET_DIR="$BENCH_TARGET_DIR" \
SHA256_BENCH_WORKDIR=target/sha256-optimized-cache \
SHA256_ZK_BENCH_EXTENSION=quintic \
cargo +nightly-2026-03-04 bench --locked --features parallel \
  --bench sha256_full_zk -- \
  --save-baseline quintic_rest4_default_2026_08_26 \
  'sha256_2048b_quintic/.*/.*spark'
```

The accepted full-ZK witness row used the selected `rsv=6` override against
that saved baseline. The override matches the final helper default.

